## 2. 引言与背景目标

### 2.1 研发背景

当前市面上的 AI 图像生成工具多为像素级输出，后期手动描图耗时费力；而传统矢量化算法（如 VTracer、Potrace）缺乏语义理解，生成的 SVG 路径冗余且难以编辑。PenPaw 旨在通过"神经-符号混合架构"填补这一空白：

- **神经部分**：Stage 1 感知（SAM / DINOv2 / 方向场估计器）与 Stage 2 生成（Flow-Matching）由神经网络完成；
- **符号部分**：Stage 2 输出与 Stage 3 优化的对象是离散的 SVG 命令序列（M/L/C/Z）与贝塞尔控制点，Stage 3 通过 DiffVG 可微分光栅化对符号表示做梯度优化。

### 2.2 业务目标

验证"三阶神经-符号流水线"在简单图形和复杂图像抽象场景下的可行性。MVP 阶段核心聚焦于**简单图形/Icon 生成**与**复杂图像辅助矢量化**两大场景。

### 2.3 需求范围（MVP 边界）

**IN（做什么）：**

- Web 端核心编辑器
- 语义区域选择（ROI，基于 SAM 点选/框选）
- "线条平滑度"与"细节保留度"两个意图滑块
- 秒级实时预览（交互态 P99 < 1s）
- 后台异步终极优化导出（Stage 3）
- 基础保真度/路径复杂度定量评估看板（单图 LPIPS/SSIM + 控制点数 + 文件大小 + VTracer 对比；FID 仅用于 Golden Test Set 离线批量评估）

**OUT（不做什么）：**

- 移动端适配
- Figma/Illustrator 插件集成
- 自然语言指令驱动生成（LLM 意图对齐）
- 开放路径/骨架提取（单线描边）
- 像素级"魔棒"选区工具（移入 V2）
- 桌面端（MVP 不做；V2 方向已定为**本地推理桌面版**，技术方案见附录 E）
- 企业级私有化部署

> 术语约定：本文档中"矢量结果"均指**闭合轮廓 + 纯色填充色块**，不包含单线描边/骨架。

## 3. 用户与场景

### 3.1 目标用户画像

- **UI/UX 设计师**：需要快速生成符合品牌调性的扁平化插画或 Icon，要求导出的 SVG 图层干净，可直接在 Figma 中用钢笔工具微调。
- **数字制造从业者（POD/贴纸）**：需要将摄影照片转化为纯色块矢量图用于印花，要求 AI 能自动过滤阴影和噪点，生成干净的几何色块。

### 3.2 核心使用场景

**场景 A（灵感秒级交付）**：用户上传一张参考图，用 SAM 点选/框选核心主体，拖动"线条平滑度"滑块，右侧在秒级内实时预览生成的矢量轮廓与色块，满意后点击"快速导出"或"精细优化并导出"。

**场景 B（复杂图像抽象）**：用户上传一张包含大量树叶噪点的照片，通过 ROI 剔除背景，系统自动抽象出建筑的直线结构，点击"精细优化并导出"后在后台进行数秒（目标 P95 < 3s）的终极路径精简优化。

## 4. 核心功能需求

### 4.1 语义区域选择与意图控制模块

**功能描述**：提供可视化的交互界面，允许用户定义 AI 生成的"导航地图"。

**输入图像规范：**

| 项 | 约束 |
|----|------|
| 支持格式 | JPG / PNG / WebP |
| 最大文件大小 | 10 MB |
| 最大分辨率 | 长边 ≤ 4096 px |
| 超限处理 | 长边 > 4096 px 自动降采样至长边 2048 px 并提示"图像已自动缩放以保证处理速度"；格式/大小不支持则拒绝上传并提示 |

**业务规则：**

1. **ROI 选择**：MVP 仅支持 SAM 点选/框选（点击主体生成语义 Mask，支持拖拽框选初始化），生成语义掩码（Mask）。支持**多区域**选择，每个区域独立成组；不连通区域按 SAM 输出的连通分量处理。
2. **意图滑块**（两个，命名与说明文案如下）：
   - **线条平滑度**（0~100，默认 50）：控制轮廓的平滑程度，影响形状。
   - **细节保留度**（0~100，默认 50）：控制色块与细节的保留数量，影响区域拆分粒度。
3. **参数映射**（详见附录 A）：滑块值映射为 Stage 1 方向场平滑核、Stage 2 最大命令数上限、Stage 3 曲率惩罚与控制点惩罚系数。
4. **默认行为**：若用户未框选任何区域，默认对全图进行语义解析（全图按 SAM 自动分割为多个语义区域）。

**异常处理：**

- 若 Mask 面积 < 图像面积的 0.5%，或 Mask 包围盒 < 32×32 像素，提示"区域过小，请重新选择"，该区域不进入生成流水线。
- 若用户连续 3 次 ROI 选择被拒绝，展示操作引导浮层。

### 4.2 快慢双系统渲染引擎

**功能描述**：实现交互态的极速反馈与导出态的精细优化。

**业务规则：**

1. **快系统（交互态）**：用户调整滑块或 ROI 时，仅触发 Stage 1 + Stage 2，交互态预览 P99 < 1s（云端 T4 GPU）。
2. **请求节流**：
   - 前端对滑块/ROI 变更做 300ms debounce；
   - 每次请求携带单调递增的版本号，前端丢弃过期响应；
   - 后端对同一会话的快路径推理并发限制为 1，新请求到达时取消/丢弃该会话上一个未完成的快路径任务。
3. **慢系统（导出态）**：点击"精细优化并导出"时，触发 Stage 3（DiffVG），后台异步运行梯度寻径优化，前端展示进度条（SSE 推送）。
4. **导出交互**：结果区提供两个按钮：
   - **快速导出**：直接下载当前 Stage 2 预览结果对应的 SVG；
   - **精细优化并导出**：触发 Stage 3，完成后自动下载优化后的 SVG，并展示评估看板。

**异常处理（降级闭环）：**

- 若后台 DiffVG 优化超时（> 10s）或发生 OOM（显存溢出），系统自动降级，直接返回 Stage 2 的预览结果，并提示"当前图像过于复杂，已为您跳过终极优化"。
- 降级后允许用户**重试 1 次**；同一任务连续 2 次降级，则提示"该图像建议直接导出预览结果"，并置灰"精细优化并导出"按钮。
- 降级返回的结果**计入导出成功**（见 §7）。
- Stage 3 队列深度限制为 20 个任务，超出时前端展示预计等待时间；排队超过 60s 未开始执行则提示用户稍后再试。

### 4.3 定量评估与 Baseline 对比看板

**功能描述**：在导出结果页，客观展示当前生成质量的量化指标。

**业务规则：**

1. **单图指标**（导出结果页实时展示）：
   - **LPIPS**（对原图，感知保真度，越低越好）
   - **SSIM**（对原图，结构相似度，越高越好）
   - **控制点数量**（Path Complexity，全 SVG 贝塞尔控制点总数）
   - **SVG 文件大小**（实际序列化后的字节数，非估算）
2. **VTracer 对比**：在**上传时后台预计算** VTracer baseline（参数取官方默认值）并缓存（与资产同生命周期，24h TTL），导出页直接读取展示：VTracer 控制点数、文件大小、LPIPS/SSIM。
   - "控制点减少 > 30%"的对比口径：当 VTracer 输出与 AI 输出的 LPIPS（对原图）差值 < 0.02 时（视为同等视觉还原度），比较二者控制点数量。
3. **FID**：不在单图页面展示（FID 为集合级指标，无法对单图计算）。FID 仅在 Golden Test Set 离线批量评估报告中展示（200 张生成图 vs 200 张原图）。
4. **降级场景**：降级返回 Stage 2 结果时，评估看板正常展示，并标注"未执行终极优化"。
5. **验收标准**：所有指标计算口径需与附录 C 的 Golden Test Set 评估脚本一致；导出页指标数据加载延迟 < 500ms。

## 5. AI 专属核心模块规范

### 5.1 模型故事与 Agent 工作流（三阶流水线）

**Stage 1 — 感知（三个子模块）：**

| 子模块 | 模型 | 输出 |
|--------|------|------|
| 语义分割 | SAM | 语义 Mask（ROI 交互 + 全图自动分割） |
| 语义特征 | DINOv2 | 区域语义特征（用于色块聚类、置信度计算） |
| 方向场估计器 | 独立轻量模型（边缘梯度方向 + 语义先验） | 切线流（tangent flow） |

> 注：切线流**不是** SAM/DINOv2 的直接输出，方向场估计器为独立模型，需单独排期与验收（见 §6 风险预案 R1）。

**Stage 2 — 生成**：基于 Flow-Matching 理论的层级生成。在**连续潜空间**执行 flow matching 采样，再经离散化解码器输出 SVG 命令序列（M/L/C/Z）。输入：Stage 1 的 Mask + 切线流 + 语义特征 + 滑块映射参数。

**Stage 3 — 优化**：DiffVG 可微分光栅化 + 梯度下降，对 Stage 2 输出的控制点做视觉还原优化与路径精简。Loss 构成：视觉还原项（对原图/ROI 内原图）+ 曲率平滑惩罚（λ_c）+ 控制点数量惩罚（λ_p）。MVP 阶段**放宽拓扑约束权重**，优先保证视觉还原（见 §6 风险预案 R0）。

### 5.2 模型能力边界与降级策略

- **适用场景**：简单 Icon、Logo、扁平化插画、照片的语义抽象。
- **禁用/降级场景**：极高分辨率（> 4K）的复杂工业图纸、密集细节照片。行为定义：
  - 分辨率超限：按 §4.1 输入规范自动降采样处理（不拒绝）；
  - 内容复杂度超限（区域数 > 15 或 Stage 2 置信度极低）：跳过 Stage 3，直接走降级路径（不计入导出失败）。
- **置信度分层**：
  - 置信度 = Stage 2 生成似然分数与 Stage 3 自交叉检测分数的复合分数（0~1，具体权重由算法组在 M3 里程碑前定稿并写入接口文档）；
  - **高置信度（≥ 0.7）**：直接展示终极优化结果；
  - **低置信度（< 0.7）**：高亮提示"路径可能存在自交叉，建议人工精修"；
  - 自交叉检测算法：贝塞尔段相交检测（Stage 3 输出后同步执行，耗时 < 200ms）。

### 5.3 模型交付物标准

- **输出格式**：标准 SVG 1.1 规范，具体结构约束见附录 B。
- **预期延迟**（云端 T4 GPU）：
  - Stage 1 + Stage 2 综合：**P99 < 1s**（交互态）；
  - Stage 3：**P95 < 3s，P99 < 5s**，硬超时 10s（触发降级）。

## 6. 非功能需求与风险管理

### 6.1 性能要求

- Web 端首屏加载 < 2s（国内网络 + CDN 环境）；
- **MVP 并发**：快路径（Stage 1+2）并发 5~10 路（T4）；Stage 3 队列深度 20（见 §4.2）；
- **V2 目标**：50 QPS，需根据云端 GPU 资源弹性扩容（移出 MVP 验收范围）。

### 6.2 安全与合规

- **数据生命周期**：用户上传的图片及生成的 SVG 资产，服务器端仅保留 24 小时用于缓存与 Debug，超时自动销毁。前端展示资产剩余有效期；剩余 2 小时且用户有活跃会话时提示"请及时下载"。
- **版权告知**：MVP 为匿名使用（无账号体系）。首次使用时弹窗告知 AI 生成内容的版权归属与免责声明，用户勾选确认后进入编辑器，确认行为记录日志（合规留痕）。告知文案需经法务审核后上线。
- **项目开源许可（Apache-2.0）**：
  - 项目**代码**以 Apache License 2.0 发布（仓库根目录 `LICENSE` 已就位）；
  - **模型权重与代码许可分离**：权重不存入代码仓库，通过下载脚本按需获取；下载脚本必须逐条标注每个权重的许可证名称与来源链接；
  - **默认配置仅允许商用友好权重**（Apache-2.0 / MIT / CC-BY-4.0 等允许商用的许可）；CC-BY-NC / FAIR 非商用许可的权重（如 DINOv2 仓库内的 Cell-DINO / XRay-DINO 子模块）禁止出现在默认配置中，代码层面显式拦截（见 R3）；
  - 仓库需维护 `THIRD_PARTY.md`（或 `NOTICE` 文件），列出全部第三方依赖及其许可证，满足 Apache-2.0 §4 声明保留要求；
  - 贡献者首次提交需签署 CLA（Contributor License Agreement），保证开源链版权清晰。
- **内容安全**：
  - 输入侧：Stage 1 入口接入内容安全过滤 API（选型：国内部署用阿里云/腾讯云内容安全，海外部署用 OpenAI Moderation，以最终部署地域为准，M1 前确定）；
  - 输出侧：对最终栅格化预览图做**异步**复检（不阻塞导出），命中则标记该资产并提示。

### 6.3 风险预案

| 编号 | 风险 | 应对 |
|------|------|------|
| R0 | DiffVG 拓扑约束与视觉还原 Loss 冲突导致优化失败 | MVP 阶段放宽拓扑约束的权重，优先保证视觉还原，将"完美拓扑"作为 V2 攻坚目标。同时监控**自交叉率**指标，量化放宽约束的影响 |
| R1 | 方向场估计器效果不达标，锁死 Stage 2 生成质量上限 | 设置验收门禁：方向场单独验收，方向角误差 < 15° 的像素占比 > 85%（在 Golden Test Set 上）。不达标则 Stage 2 输入退化为纯 Mask + 边缘，不阻塞 M3 |
| R2 | DiffVG 显存/时间随区域数与控制点数超线性增长，复杂照片集上导出成功率不达标 | 按区域数分档：≤5 区域全量优化；6~15 区域分批优化；>15 区域直接走降级路径（不计入失败） |
| R3 | 模型许可证合规：经核实，SAM 代码与权重均为 Apache-2.0；DINOv2 主代码 Apache-2.0、主预训练权重 **CC-BY-4.0（允许商用，需署名）**。无传染性风险，仅剩署名义务。但 DINOv2 仓库内 **Cell-DINO / XRay-DINO 生物医学子模块为 CC-BY-NC / FAIR 非商用许可**，若误用将构成对下游商用者的侵权 | ① 仅使用 DINOv2 主预训练权重（ViT-S/B/L/g14 系列），**代码与配置中显式禁止引用 cell_dino / xray_dino 路径**；② 权重下载脚本逐条标注许可证（DINOv2: CC-BY-4.0, SAM: Apache-2.0）；③ 在 `THIRD_PARTY.md` 与产品"关于/许可"页面保留 Meta AI 署名（CC-BY-4.0 义务）；④ M1 许可证审计时复核上述结论并写入技术设计文档 |
| R4 | AI 生成的 SVG 包含敏感元素 | 见 §6.2 内容安全（输入 + 输出双侧过滤） |
| R5 | VTracer（visioncortex/vtracer）为 **MIT** 许可，与 Apache-2.0 兼容，无传染性风险。仅剩 MIT 的声明保留义务（分发时需保留其版权声明与许可文本） | 直接以官方 Python 库（`pip install vtracer`）集成，作为上传时 baseline 预计算组件；在 `THIRD_PARTY.md` 中登记 VTracer（MIT, visioncortex/vtracer）即可，无需进程隔离 |

## 7. 评估指标与验收标准

### 7.1 技术指标

| 指标 | 目标 | 计算口径 |
|------|------|---------|
| ROI 提取准确率 | > 90% | 在 Golden Test Set 标注的 Mask ground truth 上，生成 Mask 与 ground truth 的 IoU > 0.8 记为正确，正确率 > 90% |
| 方向场准确率 | > 85% | 方向角误差 < 15° 的像素占比（R1 门禁） |
| 导出成功率 | > 95% | 成功导出（含降级返回 Stage 2 结果）/ 总导出请求。降级计成功 |
| 交互态延迟 | P99 < 1s | Stage 1+2 端到端（T4） |
| Stage 3 延迟 | P95 < 3s / P99 < 5s | 硬超时 10s |

### 7.2 业务指标

| 指标 | 目标 | 评测方法 |
|------|------|---------|
| 编辑成功率（Figma/Illustrator） | > 80% | 见 §7.4 人工评测协议 |
| 控制点精简率（简单图形场景） | 较 VTracer 减少 > 30% | 同等视觉还原度口径：VTracer 与 AI 输出的 LPIPS（对原图）差值 < 0.02 时比较控制点数量，取 100 张简单图形场景均值 |
| POD 色块纯净度 | 定性达标 | 100 张复杂照片场景中，人工抽检 20 张，阴影/噪点残留可接受比例 > 80%（2 名评测人一致） |

### 7.3 Golden Test Set 规范（详见附录 C）

- 构成：100 张简单图形（Icon/Logo/扁平插画）+ 100 张复杂照片；
- 所有 §7 指标需在该测试集上达到最低达标阈值方可上线；
- 评估脚本纳入 CI，模型/流水线每次更新自动回归，防止指标退化。

### 7.4 编辑成功率人工评测协议

1. 从 Golden Test Set 的导出 SVG 中分层抽样 50 张（简单图形 30 + 复杂照片 20）；
2. 2 名设计师各自在 Figma 中对每张 SVG 执行固定操作清单：
   - 钢笔工具拖动任意 3 个节点；
   - 对任意 2 个图层执行布尔并集；
   - 对任意 2 个图层执行布尔差集；
   - 执行"路径 > 查找问题路径"，记录报错数；
3. 单张 SVG 判定为"编辑成功"：无崩溃、无布尔运算失败、节点可正常拖动；
4. 通过率 = 编辑成功张数 / 50，需 > 80%（两名设计师结果取均值）。

## 附录 A：滑块参数映射表

| 滑块 | 范围 | 默认值 | 映射目标 |
|------|------|--------|---------|
| 线条平滑度 S | 0~100 | 50 | ① Stage 1 方向场高斯平滑核 σ = 1 + (S/100) × 5（像素）；② Stage 3 曲率惩罚 λ_c = 0.01 × (S/50)² |
| 细节保留度 D | 0~100 | 50 | ① Stage 2 最大命令数上限 N_max = 200 + (D/100) × 800；② Stage 3 控制点惩罚 λ_p = 0.005 × (1 − D/100) + 0.001 |

- 联动规则：两滑块独立，无禁用联动；
- 具体系数初值由算法组在 M2 里程碑调参后定稿，定稿值更新本表并同步测试用例。

## 附录 B：SVG 交付物结构规范

1. 符合 SVG 1.1 规范，根元素包含 `viewBox`（与输入图像像素坐标一致）；
2. 每个语义 Mask 区域对应一个 `<g>` 分组，带 `id`（`region-{n}`）与 `data-label`（区域语义标签）；
3. 仅使用纯色 `fill`，**不使用** filter、gradient、mask、clipPath 等 Figma 兼容性差的特性（MVP 限制）；
4. 坐标与路径数值精度为 2 位小数；
5. 路径均为闭合路径（以 Z 结尾），无开放路径；
6. 文件头部注释包含生成参数（滑块值、模型版本号、时间戳），便于 Debug 追溯。

## 附录 E：V2 桌面端本地推理版（方案 B）技术方案概要

> 状态：V2 规划，MVP 不实施。本节为方向性技术约定，V2 立项时需扩展为独立技术设计文档。

### E.1 架构

```
┌─ Tauri 2 桌面应用 ────────────────────────────────┐
│  React 前端（复用 apps/web，API 层替换为本地调用）    │
│  Tauri Command/SSE → Python sidecar 进程           │
│  ┌─ Python sidecar（uv 管理 venv + PyTorch）─────┐ │
│  │  packages/pipeline 三阶流水线（与云端同一份代码）│ │
│  │  设备路由：CUDA / MPS / CPU 自动选择            │ │
│  └───────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────┘
```

- **代码复用**：`packages/pipeline` 保持设备无关（`torch.device` 注入），云端 worker 与桌面 sidecar 调用同一份流水线代码——这是 MVP 脚手架必须遵守的约束；
- **前端复用**：`apps/web` 的 API 客户端抽象为接口（`CloudClient` / `LocalClient`），Tauri 环境下注入 LocalClient（走 Tauri Command + 事件通道替代 HTTP/SSE）。

### E.2 硬件分级与性能指标重定义

| 档位 | 硬件 | 预期交互态延迟 | Stage 3 |
|------|------|---------------|---------|
| 高 | NVIDIA RTX 3060 8G+ / Apple M1 Pro+ | P99 < 2s | P95 < 10s |
| 中 | RTX 3050 / M1 基础款 | P99 < 4s | P95 < 20s 或自动降级 |
| 低 | 无独显 / CPU only | 不承诺实时预览（提示"处理中"） | 默认跳过 Stage 3 |

- MVP 的 P99 < 1s / P95 < 3s 指标**仅适用于云端 T4 形态**，桌面端按上表独立验收；
- 前置技术验证（V2 立项门禁）：① 三模型在 **macOS MPS** 的兼容性验证（DiffVG 的 MPS 支持需 POC）；② 模型量化方案（FP16/INT8）使内存占用 ≤ 8GB；③ 无 GPU 档位的 CPU 推理耗时基线。

### E.3 模型分发与许可

- 模型不随安装包内置（SAM 2.5GB + DINOv2 ~1.2GB + 方向场，合计 4GB+），**首次启动按需下载**（断点续传 + SHA256 校验），缓存于用户数据目录；
- 下载源需自托管镜像（避免依赖 HF 可用性），模型清单逐条标注许可证（DINOv2: CC-BY-4.0、SAM: Apache-2.0）；
- 安装包"关于"页与首次启动流程展示完整第三方许可文本（满足 Apache-2.0 §4 与 CC-BY-4.0 署名义务）；
- 三平台打包：macOS（Universal2 + notarization）、Windows（code signing）、Linux（AppImage/deb）。

### E.4 合规与安全（相对 Web 端的增量优势）

- **数据不出本机**：原图与生成 SVG 仅存于本地，天然满足甚至超越 §6.2 的 24h 数据生命周期要求（本地缓存由用户自主管理 + 提供一键清除）；
- 内容安全过滤（§6.2）在本地形态下改为**本地轻量分类器**预筛 + 可选云端复检（用户可关闭，关闭时在 UI 声明责任）；
- 版权告知弹窗（§6.2）流程不变。

### E.5 工作量与排期预估

- 预估 **2~3 人月**（不含前置 POC）：sidecar 工程化 0.5、MPS/CUDA 适配与量化 0.5~1、模型分发与三平台打包签名 0.5~1、本地形态验收测试 0.5；
- 建议排期：MVP（Web 端）上线并稳定运行后启动，作为 V2 首个里程碑（V2-M1）。
